# Context.md — Технический контекст проекта

Этот документ предназначен для разработчиков и языковых моделей (LLM) для быстрого погружения в архитектуру и логику работы репозитория.

## Архитектура системы

Приложение построено по асинхронной схеме и состоит из двух основных компонентов:
1. **Backend (FastAPI, папка `app/`):** Поставляет REST API для работы с каталогом предложений, заказами и общей статистикой. Включает встроенную генерацию демонстрационных данных при старте.
2. **Telegram Bot (`bot/`):** Асинхронный сервис на базе библиотеки aiogram 3, обращающийся к Backend через клиент `httpx`.

---

## Назначение модулей

### `bot/config.py`
Загружает и парсит переменные из `.env`. Выполняет валидацию значений (извлечение числовых значений из текстовых строк, приведение ссылок Web App к HTTPS).

### `bot/api_client.py`
Содержит определение структуры `Offer` и асинхронный клиент `ApiClient`. Метод `Offer.from_api()` выполняет нормализацию названий полей, поступающих из разных версий API.

### `bot/storage.py`
Реализует работу с локальной базой данных SQLite через потокобезопасные вызовы (`threading.Lock`). Хранит привязки заведений к чатам, историю заказов, подписки пользователей на города и реестр пользователей для рассылки.

### `bot/notifier.py`
Фоновый процесс `poll_new_offers`. Опрашивает API с заданным интервалом и рассылает уведомления подписанным пользователям при появлении новых позиций.

### `bot/ads.py`
Фоновый процесс `ads_loop`. Реализует циклическую отправку информационных сообщений из списка `ADS` по всей базе зарегистрированных пользователей.

### `bot/handlers/`
* `customer.py`: Сценарии взаимодействия с покупателем (поиск, FSM-процесс оформления заказа, история, управление подписками).
* `cafe.py`: Сценарии авторизации заведения и добавления новых предложений через FSM.

### `lifespan_example.py` и `app/main.py`
Используют механизм FastAPI lifespan для параллельного запуска бота в едином event loop с веб-сервером.

## Потоки данных (Data Flow)

### Сценарий оформления заказа
1. Пользователь инициирует заказ в боте.
2. Бот собирает данные через FSM и вызывает `ApiClient.create_order()`.
3. Запрос направляется на Backend (`POST /api/orders`).
4. При успехе бот ищет `chat_id` создателя позиции в таблице `offer_owners` и отправляет ему уведомление с деталями заказа.
5. Заказ записывается в локальную историю `user_orders`.

### Сценарий добавления позиции заведением
1. Пользователь проходит авторизацию по `CAFE_ACCESS_CODE`.
2. Заполняет параметры предложения через FSM.
3. Бот отправляет `POST /api/offers` на Backend.
4. Полученный ID предложения связывается с `chat_id` автора в SQLite, чтобы корректно адресовать будущие уведомления.
